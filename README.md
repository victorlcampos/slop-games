# 🕹️ slop-games

Games that run entirely in the browser. Each one is **a single HTML file** — no
server, no install, no account.

▶️ **[Play](https://victorlcampos.github.io/slop-games/)**

---

Not one of them ships a single image: sprites, terrain, textures and sound are
all generated by code at load time. Even the 🇧🇷/🇺🇸 flags in the language
picker — the emoji has no glyph on Windows, so they are drawn on a canvas.

**Every game speaks English and Portuguese.** The choice covers the whole
catalog: switching the flag on the index switches it in whatever game you open
next.

**Install it and it works with no signal.** Add the catalog to your home screen
and the whole thing — the index and all seven games — is kept on the device, so
it opens on a plane, on the underground, or with the wifi off. A single
self-contained file still has to be *downloaded* once; that is what the service
worker behind the catalog is for. With a connection you always get the current
build.

## Running locally

```bash
npm install       # once
npm run open      # builds everything and opens the index in a browser
```

The build produces `dist/index.html` (the index) and `dist/<slug>/index.html`
(each game). They all open on a **double click** — no local server.

```bash
npm run build              # build everything
npm run build zoo-magnata  # build one game
npm test                   # the whole suite, in about three seconds
```

## Adding a game

The house rules — technologies, the build contract, what is not up for
negotiation — live in **[CLAUDE.md](CLAUDE.md)**. The short version: a
self-contained `index.html`, zero CDN, assets generated by code, esbuild as the
bundler.

The index is generated from `games/*/game.json`, so a new game shows up on its
own after a build.

## On a phone

Open **[the catalog](https://victorlcampos.github.io/slop-games/)** and use "Add
to Home Screen" (iOS) or "Install app" (Android). It becomes a single icon with
every game inside — and from inside a game, the exit on the home screen takes
you back to the list.

## On Omarchy

There is an [Omarchy](https://omarchy.org) shell plugin for this catalog: a
gamepad on the bar, the ten games in the panel under it, each one opening in its
own window.

```
omarchy plugin add https://github.com/victorlcampos/omarchy-slop-games.git --enable
```

Its source is here, in **[omarchy/](omarchy/)** — the panel, the rules behind it,
and the generator that keeps its list of games in step with `games/`. What gets
published is a repository of its own, assembled by `npm run omarchy:publish`:

```bash
npm run omarchy:publish     # -> dist-omarchy/, six files, ~28 KB
```

**Why it is not this repository.** It was, for an afternoon. But `omarchy plugin
add` clones whatever URL you give it, so installing a bar widget meant cloning
16 MB of games — and the marketplace's static scan, which refuses any scanned
file over 512 KB, choked on SkiFree's 1.3 MB vendored three.js. A file the
plugin never reads, in the clone only because it lived in the same repository,
sank the listing. The plugin ships as its own repository now and this one stays
its source.

Everything else about it — the keybind, the two languages, what it needs and
what it writes — is in [omarchy/README.md](omarchy/README.md), which is also the
published repository's README.

## Publishing

Push to `main` → GitHub Actions **runs the tests and only publishes if they
pass**. What goes live is the exact artifact that was tested, not a fresh build.
A pull request runs the same tests without publishing. `dist/` is not committed.

## Tests

```bash
npm test               # the kit's unit tests + the catalog floor
npm run test:games     # each game's own test
```

**Nothing here opens a browser, and the whole thing takes about three seconds.**
The floor reads the built files (one self-contained `index.html`, both
languages, the exit to the catalog, an installable manifest); each game's own
test plays it in Node — the skier accelerates and the Yeti eats him, the car
reaches a top speed, an animal is planted and a monster dies, 219 species are
all well formed.

The one thing a test cannot say any more is "and it draws": CI has no graphics
card, and a scenario that played a 3D game there measured the software renderer
instead of the code. That is a two-minute lap by hand before a deploy — see
[CLAUDE.md, section 6](CLAUDE.md) for the whole story.
